# Decide

`POST /decide` accepts a flat payment payload with nested `card` and `routing_config` objects. It runs the same hybrid evaluator as [`/routing/hybrid`](/decision-engine-api-reference/api-reference/guides/configure-routing/routing-hybrid) — rule selection, Auth Rate routing, A/B experiments, scoring, and fallback handling.

Send the same authentication and tenant headers used for `/routing/hybrid` (`Authorization: Bearer <token>` or `x-api-key: <key>`). Merchant sessions and API keys may only name their own `merchant_id`. A cross-merchant request returns `403`. Service callers can use the existing `x-admin-secret` header to act for the named routing scope. `/routing/hybrid` continues to accept its existing request and return its existing response.

## Full request

```bash
curl --location "$BASE_URL/decide" \
  --header "$AUTH_HEADER" \
  --header "Content-Type: application/json" \
  --data '{
    "payment_id": "pay_demo",
    "merchant_id": "pro_demo",
    "amount": 1000,
    "currency": "USD",
    "payment_method_type": "card",
    "payment_method_sub_type": "credit",
    "billing_country": "US",
    "card": {
      "card_isin": "001234",
      "card_extended_bin": "00123456",
      "card_network": "Visa",
      "card_type": "credit",
      "card_issuing_country_code": "US"
    },
    "metadata": {
      "segment": "premium"
    },
    "routing_config": {
      "algorithm_for": "payment",
      "eligible_connectors": [
        { "gateway_name": "worldpay", "payment_merchant_connector_id": "mca_wp" },
        { "gateway_name": "checkout", "payment_merchant_connector_id": "mca_cko" }
      ]
    }
  }'
```

The required fields are `payment_id`, `merchant_id`, `amount`, `currency`, `routing_config.algorithm_for`, and `routing_config.eligible_connectors`. Every input connector requires a nonempty `gateway_name` and `payment_merchant_connector_id`. Other fields may be omitted or null. Amounts are unsigned integers in minor units. BINs are strings and preserve leading zeros.

## Field mapping

| `/decide` field | Existing internal field |
| --- | --- |
| `amount` | static `amount` and `payment_amount`, plus dynamic payment amount |
| `payment_method_type` | static `payment_method` |
| `payment_method_sub_type` | static `payment_method_type` |
| `card.card_isin` | `card_bin` |
| `card.card_extended_bin` | `extended_card_bin` |
| `card.card_issuer` | `issuer_name` |
| `card.card_issuing_country_code` | `issuer_country` |
| Root `merchant_id` | static `created_by` / dynamic merchant ID |
| `routing_config.eligible_connectors` | hybrid candidate/fallback input |
| `payment_merchant_connector_id` | `gateway_id` / account-qualified dynamic connector |

Country codes use ISO alpha-2 values. The adapter translates them to the configured country names for rule matching. Other configured enum values retain an exact match when available, otherwise a case-insensitive match. Existing rule schemas and stored configurations keep their current names.

`merchant_id` is the routing scope formerly called `created_by`. Integrations must continue sending the same identifier (the Hyperswitch profile ID where applicable). `routing_config.algorithm_for` remains explicit and required. It is not inferred from `payment_id`.

`amount` is the single payment amount in this contract. It supplies both existing rule parameters, `amount` and `payment_amount`, without changing stored rule definitions. `metadata` supplies custom rule parameters without overwriting configured or reserved fields. `authentication_type` supplies both rule and dynamic authentication data. Preferred accounts and ranking/elimination options are forwarded to the existing decider. Feature and experiment gates still control whether it runs. `country` takes precedence over `billing_country`, then `business_country`.

The removed fields (`payment_type`, `transaction_type`, EMI fields, `internal_metadata`, `order_amount`, `payment_amount`, `udfs`, `payment_metadata`, `payment_source`, `auth_type`, and `channel`), old `context` / `created_by`, top-level card fields, and `fallback_connectors` are not accepted by `/decide`. Other endpoints retain their existing contracts. Missing required fields, unknown fields, and incorrect JSON types return `400` in the standard invalid-request format.

## Response

```json
{
  "static_routing": {
    "payment_id": "pay_demo",
    "status": "success",
    "output": {
      "type": "priority",
      "connectors": [
        { "gateway_name": "worldpay", "gateway_id": "mca_wp" },
        { "gateway_name": "checkout", "gateway_id": "mca_cko" }
      ]
    },
    "evaluated_output": [
      { "gateway_name": "worldpay", "gateway_id": "mca_wp" },
      { "gateway_name": "checkout", "gateway_id": "mca_cko" }
    ],
    "eligible_connectors": [
      { "gateway_name": "worldpay", "gateway_id": "mca_wp" },
      { "gateway_name": "checkout", "gateway_id": "mca_cko" }
    ]
  },
  "dynamic_routing": {
    "status": "success",
    "decision": {
      "decided_gateway": "worldpay",
      "fallback_gateways": ["checkout"],

      "filter_wise_gateways": null,
      "priority_logic_tag": null,
      "routing_approach": "SR_SELECTION_V3_ROUTING",
      "gateway_before_evaluation": "worldpay",
      "priority_logic_output": {
        "isEnforcement": false,
        "gws": ["worldpay", "checkout"],
        "priorityLogicTag": null,
        "gatewayReferenceIds": {},
        "primaryLogic": null,
        "fallbackLogic": null
      },
      "debit_routing_output": null,
      "reset_approach": "NO_RESET",
      "routing_dimension": "ORDER_PAYMENT,CARD,CREDIT,UNKNOWN",
      "routing_dimension_level": "CARD_LEVEL",
      "is_scheduled_outage": false,
      "is_dynamic_mga_enabled": false,
      "gateway_mga_id_map": null,
      "is_rust_based_decider": true,
      "latency": 2,
      "multi_objective_info": null,
      "volume_steer_info": null
    },
    "fallback_connectors": null
  },
  "evaluated_connectors": [
    { "gateway_name": "worldpay", "gateway_id": "mca_wp" }
  ]
}
```

`evaluated_connectors` is the list clients should consume. Prefer it over the per branch outputs.

`static_routing` reports the rule evaluation. `status` says how the rule resolved, `output` carries the rule result and its type, and `evaluated_output` and `eligible_connectors` show the candidates considered.

`dynamic_routing` reports the scoring decision. `decision.decided_gateway` is the winning connector, `fallback_gateways` is the order to retry in, `gateway_priority_map` holds the per gateway scores, and `routing_approach` identifies the approach that produced them.

The endpoint preserves the connector order, selection, and errors of the routing evaluation. When there is no active rule, the supplied candidates can still be returned as a fallback. Candidate filtering still applies: a rule output outside the supplied candidate list falls back to eligible candidates. If a legacy rule returns only a gateway name, its account ID is null.

Analytics add the original `/decide` request and response and identify the API route as `decide`. Decisions remain in the same analytics and A/B experiment family as `/routing/hybrid`.
