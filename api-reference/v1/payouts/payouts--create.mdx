---
openapi: post /payouts/create
---

Create a payout with `payout_method_data` (including raw card details) or a saved `payout_method_id`.

## Customer creation

Create the customer separately using `POST /customers`, then pass the returned ID in `customer.id` or `customer_id` when creating the payout:

```json
{
  "amount": 1000,
  "currency": "USD",
  "customer": {
    "id": "cus_y3oqhf46pyzuxjbcn2giaqnb44"
  }
}
```

Payouts never create customers. An unknown customer ID returns `CustomerNotFound` (HTTP 404), even when customer details are included. Inline customer details other than `customer.id`, including the deprecated top-level customer details, are ignored and never create or update a customer. Use the Customers API to manage those details.

The customer association is fixed when the payout is created. Update and confirm use the customer ID stored on the payout and ignore any customer IDs supplied in those requests.

Without a customer ID, the payout remains customerless even if inline customer details are supplied. Customerless drafts remain supported where the payout flow permits them. Operations that require a customer, including supplying raw `payout_method_data`, require an existing customer ID. To create a payout link, pass the existing customer ID in the top-level `customer_id` field.

## External-vault card payouts

Use a card saved during a payment. Provide a unique `payout_id`, the saved `payout_method_id`, and the card owner's `customer_id` or `customer.id`.

Set `confirm=true`, `auto_fulfill=true`, `payout_type=card`, and `recurring=false`. These values apply when omitted for external-vault payouts. Send the request from your server; no separate confirmation call is required. For this flow, use the saved `payout_method_id` instead of inline `payout_method_data`. Do not send vault tokens or credentials.

## Retry handling

After a timeout, retrieve the payout using its `payout_id` before submitting another request. Do not create a new payout ID to retry the same payout.

Creating a payout with an existing `payout_id` returns a duplicate-payout error. Use `merchant_order_reference_id` for reconciliation, not retry protection.
