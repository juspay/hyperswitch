# Step 1 decision and correction register

All choices below are **proposed**, not approvals. Named accountable owners remain unassigned under [Q1/Q8/Q11](../questions.md). No production values, seed entries, presentation defaults or SDK behavior were changed.

| Item | Source / independent expectation | Proposed decision and separate change scope |
|---|---|---|
| Four Adyen issuer aliases | API online-banking variants and W payload paths agree; compiled source path uses open-banking names. M-* fixes expected write/read paths explicitly. | Approve four exact connector/method/type bindings only; preserve UK. Any H Rust path correction requires separate legacy prefill/output tests and a business-data commit. |
| Givex | Both alias families share nested `gift_card.givex` payload paths; first included descriptor wins before display sorting. | Retain proposed `gift_card.number/cvc` IDs for this binding; reject ambiguous active aliases pending review of both orders/layouts. Do not globally strip `givex`. SDK dedup changes require their own W/U scope. |
| BankType | H wire enum is lowercase; actual W generic select preserves literal case. ACH and EFT component payload cases pass; full bank-debit checkout remains unexecuted. | Approve `checking`/`savings` payloads. Separately migrate capitalized presentation defaults/overrides with affected reader evidence; no incidental lowercasing in the harness/renderer. |
| Country ALL | Actual W consumer only matches ISO strings; no sentinel expansion. | Supply a versioned, ordered approved catalog to future pure inputs. Four-country sample only demonstrates the contract. Full catalog and seed AC/TA versus fallback coverage remain open. |
| Nordea comma | Single `DK,FI,NO,SE` string is not a code. | Refuse affected activation until a separately reviewed H source-data correction supplies the four codes, or scope is explicitly excluded without adoption/writes. No automatic split or skip. |
| Empty/missing/state options | Generic/Country/BankNamesSelect have no usable choices; State missing/empty/zero-match yields all asset states. | Keep omission versus explicit emptiness distinct; validate by render kind. Do not silently normalize state order or treat invalid allowlists as restrictions. |
| Card/Debit and connector order | W generic card path chooses Debit; U first descriptor per write path wins across eligible connectors. | Keep actual enum assignments; block unsupported credit-only differences and unapproved order conflicts. | Scope dimensions / mandate | Actual constructor omits currency/provider; client recurring/unknown decode to non-mandate. H may supply broader context/partial filters. | Do not invent missing dimensions to obtain a passing browser expectation. Full H CIT/partial-filter and affected reader comparisons remain required; SDK expansion is separate. |
| Defaults / malformed data | JS adds keys absent from defaults, Rust omits them; U can tolerate absent metadata/options/references. | Treat these as incompatible prerequisites. The local harness diagnoses null options/missing references; future whole-plan preflight must refuse all malformed or unsupported input before writes. |
| Snapshot / assets | Local fresh/retained/restored checkout and asset cases pass. Successful `{}` asset JSON decodes empty countries/null states without fallback; asset wire keys are `country` / row `value`. | Define asset validation/fallback requirements separately; do not silently repair the consumer. Certify supported assets and lifetimes in Step 11. Local synthetic replacement is not a router-cache refresh, live rollback or V4 backup test. |
| Config-fetch failure | Actual V1 PaymentElementRenderer shows the whole-form load error on SDK-config HTTP 503; it does not render an ordinary card form. Component-level missing config separately yields no dynamic fields. Both local tests pass. | Preserve this distinction in verification: failed startup is never successful required-fields acceptance. Any fail-open/fallback SDK behavior change requires separate review. |
| EPS / dummy / replacement | Effective settings, exclusions and whole-descriptor replacement affect meaning beyond requiredness alone. | Approve exact stable EPS bank inputs, dummy policy and field-type/option replacement cases before renderer goldens. No source defaults, exclusions or retirement decisions inferred from this step. |

Suggested future correction groups, **not implemented here**: H `fix: correct scoped required-field source bindings` (aliases/country after explicit review, separate if unrelated); presentation metadata migration under its configuration owner's process; W/U `fix: define card and connector required-field semantics` only if that business choice is approved. They must not be bundled into this test step or a later renderer fix.
