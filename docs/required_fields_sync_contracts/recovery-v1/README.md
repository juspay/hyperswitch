## Implemented behavior

[recovery.rs](../../../crates/router/src/core/required_fields_sync/recovery.rs) loads through the actual independent journal reader. It validates target/instance/endpoint/coordinator, recompiles and compares exact saved request bytes under the selected contract, verifies durable resolution images and reconstructs comparison state without manufacturing a CompleteInventory. Requests are classified as not dispatched, before, after or divergent. Lost creates are found by full condition and their observed server IDs are retained; no ID is guessed or ownership marker written.

Read-only classification grants no retry permission. Divergence refuses planning. A new accepted plan uses fresh complete inventory, current grants, current release intent, current prerequisites and all existing impact/case/approval checks. Confirmed after-state needs no resend; prerequisite-only progress is retained and listed by bound action hash. A verification-only successor makes zero target writes and still requires V1–V4. Its no-change outcome describes the successor; predecessor commits remain explicitly recorded in the recovery assessment.

[recovery_restore.rs](../../../crates/router/src/core/required_fields_sync/recovery_restore.rs) computes a three-way inverse using recorded before, confirmed applied and complete current rows. Absence is distinct from any value. Changed or unchanged delegated keys that diverge from their saved values refuse automatic restoration. Current unrelated overrides, descriptions and metadata are retained losslessly. Already-restored values produce no action. Restoration grants are explicitly scoped to the recorded affected conditions; they are not inferred from a marker, broad export or pending create alone.

A created row can be deleted only with current deletion delegation, exact retirement review and unchanged relevant content. If unrelated overrides were added, owned contributions are removed by replacement and that row survives. If metadata changed and no override would remain, restoration refuses: the selected wire contract cannot preserve an empty context through its nonempty override requirement. Deleted fully managed rows can be recreated from saved condition/values/description, with a fresh creation grant and pending ownership; old IDs/timestamps/priority are never fabricated. Unknown saved metadata outside the supported create wire refuses rather than being lost. The same projection/order, current dimension/default/function/experiment and bound browser gates evaluate recreation.

Extended enums and created defaults remain. The recovery report lists their action hashes; context restoration is not an inverse of the whole workspace. Separate dependency-aware administrative work is required to remove these residuals.

`RestorationDraft::bundle_hash` exposes the exact inverse bundle hash so an empty managed result can receive the existing explicit retirement manifest. This preview is not executable. `RecoveryCandidate::accept` invokes the existing exact report and approval checks. No successful placeholder report is generated by production recovery code.

`RecoveryObservation::record` re-reads the source head, rechecks external-writer/old-executor/accepted-request exclusion, verifies retained-image retention evidence, and creates/read-backs an immutable decision in the successor run namespace. It records source anchors, classification, exact current images, approvals through the accepted plan binding, new intent, residuals and exclusion evidence. The original journal and baseline remain unchanged. Renewal runs during recovery storage work; failure prevents authorization. `PreparedApply::prepare_recovery` binds that receipt to the successor plan/inventory/image/retention/run/intent. The ordinary apply preparation cannot execute a resume/restore. The existing apply engine journals the successor snapshot and every exact request before dispatch, uses one bounded context transaction, disables retries and requires the same terminal verification. Unknown commits and post-commit failures retain their existing nonzero outcomes and durable holds.

## Explicit choices, limits and pending evidence

- **Implemented conservative choice:** exact first-adoption undo uses the adoption run's confirmed after-state and protected baseline. A later run's baseline reference alone cannot prove an intervening ownership/history chain; that request refuses. Select the adoption run with the required current coordination authority, or replan a reviewed retained old bundle against current state. Divergent owned edits still require a new reconciliation. No unproved multi-run inverse is synthesized.
- **Implemented conservative choice:** unresolved request comparison is full-state under the selected contract. Concurrent/unexplained changes during an unknown outcome are divergence, even where a narrower guess might appear safe.
